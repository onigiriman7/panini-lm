External Library Integration Guide: Pāṇinian Neuro-Symbolic LLMThis document serves as the engineering blueprint for connecting external open-source linguistic tools to the PyTorch deep learning backend.Phase 1: Morphological IngestionObjective: Parse raw Sanskrit text into mathematically pure roots and affixes.Primary Library to Use: vidyut-prakriya (Rust) or sanskrit-heritage (Python wrapper).Recommendation: Use vidyut-prakriya with Python bindings (PyO3) for production due to Rust's memory safety and extreme compilation speed. Use sanskrit-heritage for rapid prototyping.How to Use It:Initialize the parser with the base Aṣṭādhyāyī ruleset.Pass the raw UTF-8 string to the Sandhi resolver function to split the sentence into padas.Pass the padas to the morphological analyzer to strip the tokens down to their prakṛti (root) and pratyaya (affix).Data Contract:Expected Input: Raw text string.Example: "rāmo'pi gṛham gacchati"Expected Output: A standardized JSON array or Python list of dictionaries containing the split tokens and their base linguistic identity.Example: ```json[{"surface": "rāmaḥ", "stem": "rāma", "type": "subanta"},{"surface": "api", "stem": "api", "type": "avyaya"},{"surface": "gṛham", "stem": "gṛha", "type": "subanta"},{"surface": "gacchati", "stem": "gam", "type": "tiṅanta"}]
Phase 2A: Pāṇinian Symbolic Engine (Syntax Track)Objective: Generate the deterministic structural routing map (Matrix $M$).Primary Library to Use: samsadhani API (University of Hyderabad) or custom implementation utilizing vidyut's metadata.Recommendation: You will likely need to write a custom Python bridge. You can query the samsadhani dependency parser API during training data preparation to get the Kāraka links, and then format those links into a PyTorch tensor.How to Use It:Extract the metadata from Phase 1.Run the symbolic logic to map the Kārakas (e.g., matching the Puruṣa and Vacana of the subject "rāmaḥ" to the verb "gacchati").Initialize a PyTorch tensor of shape (N, N) with float('-inf').Write 0.0 at indices [i, j] wherever a grammatically valid relationship exists.Data Contract:Expected Input: The JSON array from Phase 1, enriched with parsed attributes (Puruṣa, Vibhakti, etc.).Expected Output: A PyTorch Tensor representing Matrix $M$.Example: tensor([[0.0, -inf, -inf, 0.0], ...], dtype=torch.float32, device='cuda')Phase 2B: Semantic Neural Engine (Meaning Track)Objective: Map morphological tokens to dense semantic space without arbitrary positional bias.Primary Library to Use: torch.nn (Standard PyTorch).How to Use It:Map the "stem" and "type" from Phase 1 to unique integers using a custom tokenizer vocabulary mapping.Pass these integers through a standard nn.Embedding(vocab_size, d_model) layer.Crucial Step: Do not add RoPE (Rotary Positional Embeddings) or nn.PositionalEncoding. Pass the embeddings directly to the nn.Linear layers to generate $Q, K, V$.Data Contract:Expected Input: 1D Tensor of token IDs.Example: tensor([452, 12, 893, 22])Expected Output: Three dense tensors ($Q, K, V$), each of shape (batch_size, num_heads, seq_len, head_dim).Phase 3: Sparse Pāṇinian AttentionObjective: Bypass dense $O(N^2)$ computation using Matrix $M$ as a hardware-level routing map.Primary Library to Use: triton (OpenAI's kernel language) or a highly customized implementation of flash-attn.Recommendation: Write a custom triton kernel. Standard PyTorch F.scaled_dot_product_attention allows passing an attention mask, but it still computes the full $N \times N$ grid before masking, saving memory but not compute FLOPs. A triton block-sparse kernel will actually prevent the GPU from doing the math for the $-\infty$ blocks.How to Use It:Define a Triton kernel that takes $Q, K, V$, and $M$ as inputs.The kernel evaluates $M[i, j]$. If it is $-\infty$, the kernel skips the block. If 0.0, it computes dot(Q_i, K_j).Apply softmax and multiply by $V$.Data Contract:Expected Input: $Q, K, V$ tensors (from Phase 2B) and Adjacency Matrix $M$ (from Phase 2A).Expected Output: Contextualized hidden state Tensor of shape (batch_size, seq_len, d_model).Phase 4: Semantic MaturationObjective: Process complex meaning using pre-solved syntax.Primary Library to Use: torch.nn or megablocks (if implementing Mixture of Experts).Recommendation: Stick to a standard SwiGLU FFN in torch.nn initially. Because the network doesn't need to learn grammar, you can drastically reduce the expansion factor of the FFN (e.g., from the standard 4x down to 1.5x or 2x), creating a highly compressed model.How to Use It:Pass the output of Phase 3 through an RMSNorm layer.Pass through the nn.Sequential Feed-Forward Network.Data Contract:Expected Input: Contextualized hidden state Tensor from Phase 3.Expected Output: Final hidden state Tensor of shape (batch_size, seq_len, d_model).Phase 5: Grammar-Constrained DecodingObjective: Zero out grammatically impossible tokens during generation.Primary Library to Use: torch.nn.functional and your Phase 1 Morphological Engine (vidyut-prakriya).How to Use It:Project the final hidden state to vocabulary logits using nn.Linear(d_model, vocab_size).During inference, ping the Morphological Engine with the state of the previously generated token. Ask it: "What morphological types are legally allowed next?"The engine returns a boolean array. Convert this array into a PyTorch Mask Tensor ($0.0$ for legal, $-\infty$ for illegal).Add this mask to the logits: constrained_logits = raw_logits + M_decode.Apply F.softmax.Data Contract:Expected Input: 1. raw_logits: Tensor of shape (vocab_size).2. current_morphological_state: Dictionary tracking the active Padas/Pratyayas.Expected Output: A final probability distribution Tensor of shape (vocab_size) where all grammatically illegal tokens mathematically equal exactly 0.0%.
